# Underwriting & Payment Risk

A synthetic portfolio platform linking two vendor underwriting schemas to enrollment decisions, payment attempts, returns and collections. It demonstrates what was known at a decision, how outcomes mature, and why a model improvement is different from an approval-policy change.

**Status:** the $0 GCP sandbox deployment is verified in dedicated project `underwriting-risk-ez-2026`, with no linked billing account. Five dbt models and seventeen tests pass on real BigQuery; cloud readback/restoration matches the local results. See [STATUS.md](STATUS.md) and [sandbox operations](docs/SANDBOX.md).

## Run

Python 3.12 (locked, tested environment):

```sh
python -m venv .venv
. .venv/bin/activate
pip install uv==0.11.31
uv sync --frozen --all-extras
python -m unittest discover -s tests -v
python scripts/cloud_test.py
python -m risk_platform run --output artifacts/latest
python -m risk_platform verify artifacts/latest
python scripts/verify_warehouse.py
```

The batch generates 3,600 seeded applications across GBP and USD. Open `artifacts/latest/index.html` for the experiment report. `report.json` contains metrics, calibration bins, consumer-cluster Brier intervals, policy economics and operational checks; `manifest.json` pins portable artifacts with SHA-256 hashes. Existing output directories are immutable: choose a new output when changing the seed, workload or implementation.

## Data flow

Vendor A/B + enrollment/payment deliveries → append-only SQLite ledger and quarantine → normalized entities → knowledge-time features and matured outcomes → temporal baseline/challenger evaluation → currency-specific policy comparison → dbt cohort marts.

The active $0 deployment runs orchestration/model compute locally and uses BigQuery Sandbox for source snapshots, SQL/dbt transformations and marts. Tables expire after 60 days. The optional GCS/Cloud Run architecture is implemented but deferred and disabled by default in Terraform. See [GCP delivery](docs/GCP.md) and [warehouse contract](docs/WAREHOUSE.md).

## Guarantees and deliberate boundaries

- Duplicate deliveries do not alter totals. Conflicting immutable source versions roll back the ingestion transaction. Invalid records are quarantined; vendor corrections require new versions.
- Features require both an effective time and a receipt time at or before enrollment. Later backdated corrections cannot rewrite historical knowledge. Missing history stays missing; imputation is fitted on training data only.
- Payment-level exposure snapshots retain as-of time, payment age and the latest known outstanding balance, separately from windowed model outcomes. Synthetic residence/check details remain in source provenance and are excluded from scoring. The original historical score/decision is preserved under a versioned stochastic simulation policy.
- Money uses integer minor units. Attempted, settled, collected, fee revenue, costs and uncollected principal are distinct. Currencies are never combined for threshold selection or reporting.
- Labels use illustrative 30-day return and 60-day collection windows per payment. A synthetic enrollment contains all its attempts within three days. Maturity is a window rule, not proof that a source will never deliver late data. Frozen label snapshots prevent later outcomes from changing training/validation evidence.
- Train decisions: January–April 2024, labels available July 1. Validation: July, labels available October 1. Test: October, labels available February 1, 2025. Immature rows and embargo periods are excluded from model evaluation.
- Baseline: logistic regression. Challenger: gradient-boosted trees. Fixed hyperparameters; model selected by validation Brier score. Policy threshold selected from a fixed validation grid per currency. Test metrics never select models or policies. Cold-start and recurring-consumer results are separate.
- Only historically approved consumers train the models. Rejected consumers' latent outcomes exist solely in a clearly labelled synthetic counterfactual comparison; they are neither features nor observational evidence.
- Scores are retrospective experiment outputs with per-row feature/model version, decision-data cutoff and a logical experiment timestamp. They do not overwrite original decisions.
- Fee/cost assumptions: 2% of collected principal, 25 minor units per attempt, 150 per return; simulated platform bears uncollected principal. Negative contribution is a valid result. Policy economics are point estimates, not causal or real-world profit forecasts.
- Promotion/rollback is an append-only reviewed registry with concurrency checks. The generated report demonstrates it with explicitly labelled automated test fixtures; no production model is promoted automatically.

The fitted model artifacts are checksum-pinned joblib files. Their round-trip restoration reproduces every score. Load only trusted artifacts generated by this project: joblib files contain executable Python serialization.
